# OctoAcme Project Management Documentation

## Overview

OctoAcme uses a structured, iterative project management framework built on principles of **customer focus**, **clear ownership**, **data-informed decisions**, and **psychological safety**. This documentation centralizes our processes, roles, and best practices to help teams deliver projects consistently and effectively.

### Purpose of This Documentation

The OctoAcme Project Management Docs serve to:
- Provide a single source of truth for how we run projects across OctoAcme
- Accelerate onboarding by giving new team members clear process guidance
- Ensure consistency and repeatability in project execution
- Support cross-functional collaboration with defined roles and communication cadences
- Capture and refine our organizational knowledge over time

## OctoAcme Project Management Processes

OctoAcme projects follow a structured five-phase lifecycle:

### 1. **Initiation**
Define the initial business need, validate the idea, align stakeholders, and create a lightweight project charter. This phase ensures we're solving the right problem before investing in planning.

### 2. **Planning**
Turn an approved initiative into an actionable plan. Break work into shippable increments, identify dependencies and risks, define acceptance criteria, and create a prioritized backlog with clear milestones.

### 3. **Execution & Tracking**
Manage day-to-day delivery through standups, sprints, and continuous quality assurance. Track progress against metrics, manage blockers, and maintain momentum toward milestones.

### 4. **Release & Deployment**
Safely deploy features to production with clear pre-release requirements, smoke testing, rollback plans, and stakeholder communication. Minimize risk and maintain observability.

### 5. **Retrospective & Continuous Improvement**
Capture learnings after each sprint, release, or milestone. Convert insights into actionable improvements and track their impact over time.

### Key Cross-Cutting Practices

Throughout all phases, teams:
- **Manage risks proactively** — Identify, assess, mitigate, and monitor risks in a shared register
- **Communicate clearly** — Use consistent templates, regular standups, and escalation paths
- **Maintain quality** — Apply testing, code review, and acceptance criteria at every stage
- **Track metrics** — Measure progress and success based on data, not assumptions

## Core Roles at a Glance

| Role | Responsibility | Key Focus |
|------|-----------------|-----------|
| **Project Manager (PM)** | Coordinates delivery, schedules, risks, and communications | On-time, within-scope delivery |
| **Product Manager (PdM)** | Defines outcomes, prioritizes backlog, measures success | Customer value and business impact |
| **Developer** | Implements features and fixes | Code quality, maintainability, testing |
| **QA/Testing** | Validates quality and acceptance criteria | Feature acceptance and reliability |

For detailed persona descriptions, see [Roles & Personas](octoacme-roles-and-personas.md).

## Key Artifacts

Every OctoAcme project maintains:

- **Project Charter / One-pager** — Problem statement, goals, success metrics, stakeholders, timeline
- **Roadmap and Release Plan** — Milestones, delivery phases, dependencies
- **Sprint/Iteration Backlog** — Prioritized list of work with acceptance criteria
- **Risk Register** — Identified risks, impact, likelihood, mitigations, owners
- **Decision Log** — Key decisions and rationale
- **Retrospective Notes** — Learnings and action items for continuous improvement

---

## Communication Cadence

- **Daily standups** (15 min) — Progress, blockers, dependencies
- **Weekly PM + PdM sync** — Alignment on priorities and outcomes
- **Twice-weekly delivery team syncs** — Status, risks, blockers (or as agreed)
- **Monthly stakeholder updates** — Progress against milestones and success metrics
- **Ad-hoc escalations** — As needed for blockers or critical decisions

5. **Using Copilot Spaces?** Add these docs to your Space context to get project-management guidance tailored to your team.
